# Пользовательский доступ VK API

Проверено по официальным материалам VK 2026-10-20. Отсутствующий user token
не заменяется сервисным ключом, токеном сообщества или ID token.
Токен входа с базовыми доступами нельзя считать разрешением на wall/stats/market.

## Сначала проверить доступы приложения

1. В кабинете VK ID открыть своё приложение → «Доступы».
2. Сверить разрешённые приложению доступы. В проверенном новом Web-приложении
   владелец увидел только профиль, телефон и email; нужных API-доступов там нет.
3. Проверить статус профиля бизнеса. Официальная инструкция требует его
   подтверждения для расширенных доступов; часть доступов VK выдаёт только
   в исключительных случаях по обращению в `devsupport@corp.vk.com`.
4. Согласовать с VK права именно для своих методов: wall.post,
   stats.get/stats.getPostReach, market.add/edit, polls.create/edit,
   photos.createAlbum и загрузка медиа, groups.ban/unban. Указать свой
   client_id, назначение сервиса и собственные управляемые сообщества.

Список scope в OAuth-запросе не может превышать разрешённый список приложения.
Подтверждение бизнеса само по себе не гарантирует предоставление всех этих
методов. Полученный access token также не доказывает реальные права:
нужны отдельные ограниченные API-проверки.

Официальные источники:

- [Пользовательский ключ VK API](https://dev.vk.ru/ru/api/access-token/user-token).
- [Типы ключей и устаревшие способы](https://dev.vk.ru/ru/api/access-token/getting-started).
- [Настройка приложения и расширенные доступы](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/create-application).
- [Работа со scope](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/work-with-user-info/scopes).
- [Официальный PHP SDK: пользовательский OAuth](https://github.com/VKCOM/vk-php-sdk/blob/cf5b8d84440256e1595d067ef255cbc8e372eb0d/src/VK/OAuth/User/User.php).

## Современный серверный OAuth

По текущей документации VK пользовательский access token действует один час.
Для серверных запросов используется VK ID. Официальный SDK поддерживает
Authorization Code + PKCE, проверку state, device_id и refresh_token.
Эти токены VK отличаются от OAuth-токенов доступа ChatGPT к MCP.

До запуска flow оператор должен развернуть настоящий server callback,
зарегистрировать его точный HTTPS URL, сохранить state/verifier на сервере
и обеспечить обновление и ротацию VK refresh token. Registration-only страница
из nginx-шаблона для этого не подходит: она отвергает code/query.
Наличие сервисного ключа и входа ChatGPT не означает, что этот flow настроен.

Старые Authorization Code/Implicit flows получения пользовательских ключей
отключены VK с 25 июня 2024 года. Ранее выданные бессрочные и не отозванные
ключи, по документации VK, продолжают работать. Не предлагайте новые ключи
через старый oauth.vk.com/blank.html, заимствованные app ID или ввод пароля
в сторонний генератор.

## Защищённый импорт уже полученного ключа

`deploy/configure-user.py` — операторский importer существующего access token.
Он не выдаёт новые права, не реализует VK ID OAuth и не обновляет токен.
Короткоживущий ключ без отдельного механизма refresh не является постоянным
подключением. Сам importer не определяет срок жизни введённого ключа.

После получения подходящего ключа из своего приложения, в Linux SSH TTY:

```sh
sudo python3 /srv/vk-mcp/current/deploy/configure-user.py --root /srv/vk-mcp --config-dir /etc/vk-mcp --expected-user-id 123456789
```

Введите только токен в скрытый getpass. В `--expected-user-id` нужен ID личного
VK-профиля владельца, а не ID сообщества или приложения. Не отправляйте ключ,
полный redirect URL, cookies или refresh token в чат/Git/аргументы команды.

Importer проверяет пользователя через users.get без user_ids, числовую маску
account.getAppPermissions для photos, wall, groups, stats, market, video и docs,
роль администратора (`admin_level=3`) каждого разрешённого сообщества
и ограниченное чтение стены. Проверка legacy permission mask — преднамеренно
строгий контракт; несовместимый с ним современный grant не сохраняется вслепую.
Настроенные ключи, сообщества и write-профиль сохраняются. Существующий user key
не заменяется. Backup, валидация установленным parser, shared lock и rollback
защищают конфигурацию; после ошибки сначала read-back.

Успех импорта означает проверку перечисленных read-свойств, а не публикацию,
доступность полной статистики или всех методов каталога. Реальные записи
проверяют отдельно после конкретного решения владельца и root receipt.

## Шаблон запроса в VK

Подготовьте сообщение, но не отправляйте автоматически без разрешения владельца:

> Здравствуйте. Для собственного серверного сервиса управления сообществами
> требуется пользовательский доступ VK API. Приложение: CLIENT_ID, профиль
> бизнеса: BUSINESS_ID, управляемое сообщество: COMMUNITY_URL. В кабинете
> приложения доступны только vkid.personal_info, email и phone. Просим сообщить
> порядок согласования wall, photos, groups, stats, market, video и docs для
> wall.post, stats.get/getPostReach, market.add/edit, polls.create/edit,
> photos.createAlbum/загрузки медиа и groups.ban/unban. Авторизуется только
> владелец-администратор; credentials хранятся на его сервере, изменения
> выполняются после его подтверждения. Нужен официальный серверный OAuth с
> PKCE/refresh; просим уточнить ограничения методов, тип приложения и порядок
> проверки бизнеса. Если часть задач поддерживается ключом сообщества,
> просим указать актуальные разрешённые типы ключей и условия.

Не обещайте, что VK одобрит запрос. До ответа/выдачи нужных доступов отмечайте
подключение как незавершённое и сохраняйте работающие group/service credentials.
