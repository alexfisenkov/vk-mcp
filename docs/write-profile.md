# Запись, модерация и удаление

Каталог включает создание и редактирование контента, сообщения сообщества,
модерацию участников, комментарии, удаления и восстановления. Реальные права
зависят от типа credentials и разрешений VK. Наличие метода в каталоге
не даёт новых прав ключу. Большинству wall/photo/video/market-операций нужен
user token; group и service не являются его универсальной заменой.

`vk_communities` возвращает разрешённые числовые ID. `vk_capabilities`
показывает для каждого метода требуемые типы ключей, credential readiness,
локальное разрешение профиля и необходимость подтверждения. `available=true`
означает только наличие подходящих credentials и локального разрешения;
успешный живой вызов VK оно не обещает.

## Включение профиля оператором

Из проверенного Linux-релиза, с уже подготовленным root-owned approvalDir:

```sh
sudo python3 /srv/vk-mcp/current/deploy/write-profile.py --mode write
sudo python3 /srv/vk-mcp/current/deploy/write-profile.py --mode write --apply
```

Первый вызов — dry-run. При других путях добавьте `--root` и `--config-dir`.
Helper сохраняет credentials, делает защищённую резервную копию, валидирует
конфигурацию, меняет только writesEnabled и проверяет профиль после рестарта.
При неуспехе пытается вернуть предыдущую конфигурацию и проверить восстановление.
Откат тоже может завершиться ошибкой; при отказе helper сверяйте config, service
и защищённую backup-копию вручную. Проверяйте read-back;
не запускайте повторно после прерванной SSH-сессии до осмотра состояния.

Отключение: те же команды с `--mode read-only`. Перед добавлением новых
credentials через configure.py профиль требуется временно отключить.
Все config writers используют общий `onboard.lock`. Автообновление кода
существующий config не заменяет и не сбрасывает write-профиль.

## Одно действие

1. `vk_describe_method` — параметры, тип ключа и нужный community scope.
2. Named `*_plan` либо `vk_plan_write` — точный payload и десятиминутный план.
3. Владелец проверяет адресата/сообщество, объект и текст. Для удаления
   показываются конкретные идентификаторы и последствия.
4. После разрешения оператор выдаёт root-owned receipt точному hash:

```sh
sudo python3 /srv/vk-mcp/current/deploy/approve.py --config /etc/vk-mcp/config.json --plan-id PLAN_ID --hash FULL_PAYLOAD_HASH
```

5. `vk_execute_write` с plan_id и строкой confirmation из плана.
6. Read-back результата и `vk_operation_status`. При `unknown` не повторять:
   сначала установить фактический исход в VK.

План сам не отправляет запрос записи. Общая настройка «запись включена»
не подтверждает конкретную публикацию/удаление; строка confirmation не заменяет
независимое разрешение. Облачный ChatGPT не имеет root-доступа: receipt выдаёт
оператор или уполномоченный агент с SSH после конкретного решения владельца.
Во время выпуска реальные посты/сообщения/удаления не используются как тест.
Срок хранения планов, журналов и защищённых config backups пока не ограничен
автоматически; перед массовыми сценариями см. [открытые ограничения](debt.md).
