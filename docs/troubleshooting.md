# Диагностика подключения

Наблюдения 2026-10-20. Это результаты одного живого подключения,
не гарантия для других сообществ, токенов, приложений или версий VK.
Секреты, реальные ID и содержимое переписки в публичные отчёты не входят.

| Симптом | Причина и следующий шаг |
|---|---|
| Chrome automation запрещает открыть VK по site-safety policy | Это запрет инструмента, не доказательство отсутствия VK-сессии. Владелец выполняет UI-шаг вручную. Не обходить запрет через CDP, cookies или другой браузер. |
| В форме нет Standalone | Старое описание UI не универсально. Наблюдавшаяся новая форма содержит Web/Android/iOS; не обещать прежние названия пунктов. |
| «Доверенный Redirect URL» обязателен | Развернуть registration-only location по onboarding и указать собственный HTTPS URL. Пустое поле в наблюдавшейся форме не прошло. После заполнения мастер дошёл до шага 3/4, но точные сохранённые URL ещё не перечитаны. |
| Открылся шаг 3/4 «Способы быстрого входа» | Выбрать «Настроить позже»; One Tap/шторка/виджет для server service key не настраиваются. После пропуска виджетов в наблюдавшемся случае появилось «Приложение создано»; это не доказывает получение ключа. |
| Нет «Сервисного ключа доступа» | Не подставлять client secret или VK ID access token. Зафиксировать текущий экран без секретов и проверить актуальный путь выдачи ключа. |
| ID по короткой ссылке неизвестен | Получить числовой community ID из VK; helper независимо сверяет self-ID ключа. Нельзя считать короткое имя или ID профиля community ID. |
| Ключ имеет wall/photos/market flags, но методы отказали | Flags не доказывают поддержку каждого метода этим типом ключа; выполнять ограниченный read по каждому методу. |
| `not_configured` до вызова VK | Каталог не нашёл разрешённый тип credentials. Это локальная граница маршрутизации, а не ответ VK. Смотреть описание метода и наличие group/user/service, не печатая значения. |
| VK error 27 с group token | В живой проверке так отказали wall.get, photos.getAlbums, stats.get, market.get. Подбирать официально поддержанный тип credentials; не расширять policy вслепую. |
| VK error 5 только на video.get | Наблюдалось при работающих metadata/members/inbox. Один отказ не доказывает недействительность ключа целиком. |
| VK1051 на комментариях/фотоальбомах после добавления service key | В живой проверке стена с тем же ключом читалась, но wall.getComments и photos.getAlbums отказали. Сверять тип ключа/официальные доступы; не обещать, что новая выдача того же ключа исправит ограничение. |
| Нет source-bound post_id для комментариев | Сначала получить настоящий post_id доступной стены; не угадывать ID и не создавать тестовый пост автоматически. |
| video.get с service key принят VK, но core говорит not_configured | В0.2 добавлено проверенное read-only расширение token metadata для video.get; обновить проверенный SHA. Group token и права загрузки этим не расширяются. |
| VK28 на stats.get/market.get с service key | Наблюдалось при успешном wall.get. Ключ не даёт все возможности API; отдельная проверка официального типа/доступа нужна. |
| `invalid_request` / нужного параметра нет | Каталог закреплён по схеме; описания могут отставать от API или быть неполными. Проверить pinned source и официальный метод, добавить тест и минимальное совместимое изменение. |
| HTTP 401 | Нет/неверный server bearer либо proxy убрал Authorization. VK-токен не является bearer этого сервера. |
| GitHub `Invalid Redirect URI` при входе в облачный MCP | Слой owner OAuth proxy, не VK API. В наблюдении 2026-10-20 callback нового контура отсутствовал в GitHub OAuth App. Добавлен точный `/cloud/vk/auth/callback` на собственном HTTPS host, старые адреса сохранены, wildcard выключен. После сохранения и повтора входа ChatGPT показал подключённую учётную запись. Не путать callback proxy с redirect клиента ChatGPT и registration-only страницей VK. |
| ChatGPT автоматически включает OIDC для OAuth proxy | Проверить реальные metadata; если OIDC не реализован, выключить флажок до создания. Наличие OAuth discovery не доказывает поддержку OpenID Connect. |
| Карточка MCP появилась, но данных ещё нет | Создание карточки, подключённая учётная запись, загруженный каталог и успешный tool call — разные этапы. Проверить каждый отдельно, не объявлять чтение рабочим по одному UI badge. |
| HTTP 403 | Проверить Host и разрешённый Origin в config; не добавлять wildcard для обхода ошибки. |
| Непонятен JSON/SSE или клиент требует session ID | Core использует stateless Streamable HTTP с JSON-ответами. Проверить MCP SDK initialize/list/call и Accept JSON/SSE; GET /mcp не является SSE-подпиской. |
| `vk_status` имеет `isError: true`, `not_configured` | При пустых credentials это ожидаемая диагностика. Health/каталог/transport проверяются отдельно. |
| Helper отказал без TTY / токен «не виден» | Запустить интерактивно, для SSH использовать `-t`; скрытый getpass не показывает символы. Не передавать ключ аргументом. |
| Helper отказал в self-ID или service wall probe | Конфигурацию не считать обновлённой. Проверить правильный тип/источник ключа, читать безопасный статус; не перевыпускать всё вслепую. |
| Service key отказал только на первой группе | Для проверки выберите другое уже разрешённое сообщество флагом `--community-id`; helper не расширяет allowlist этим флагом. |
| Параллельное редактирование config.json | Все writer-процессы обязаны брать config-dir/onboard.lock; не редактировать файл одновременно с helper. |
| Установщик видит существующий unit/config/release | Не удалять файлы для повторной «первой установки». Читать [recovery](recovery.md), определить current/previous SHA и реальные права файлов. |
| Обновление не пришло | Сверить точный main SHA, успешный manual CI этого SHA, timer и release.json; один commit без успешной CI не достаточен. |
| Запись отклонена / исход unknown | writesEnabled=false или отсутствует независимый receipt — ожидаемый отказ. При unknown проверить журнал и VK, не повторять вызов. |

## Что подтверждено живым чтением

После скрытого ввода group token helper подтвердил принадлежность сообществу.
Через HTTPS MCP успешно прочитаны groups.getById, ограниченные страницы
участников groups.getMembers и диалогов messages.getConversations.
Наличие flags photos/docs/messages/wall/manage/stories/market не устранило
отказы методов в таблице. Эти результаты относятся к конкретному подключению;
они не переводят весь каталог в liveVerified.

Service key введён владельцем через защищённый TTY; wall.get через HTTPS MCP
успешен. wall.getComments по настоящему post_id и photos.getAlbums вернули1051;
прямой service read video.get принят VK, stats.get/market.get отказали28.
В0.2 video.get получает service routing отдельным совместимым изменением.

Не проверены: точный read-back сохранённых Redirect URL, успешное чтение
комментариев/фотоальбомов/статистики/товаров, реальные записи, полный VK OAuth,
Refresh токенов в ChatGPT и вход/Refresh в Claude. UI-вход ChatGPT через отдельный
owner OAuth proxy подтверждён 2026-10-20 после регистрации точного GitHub callback.
Работа direct HTTPS и наличие подключённой учётной записи не заменяют проверку
реальных вызовов внутри облачного клиента.

После входа через подключённый облачный коннектор отдельно подтверждены
`vk_status`, `vk_community_get`, `vk_wall_get` и `vk_videos_get` (2026-10-20).
Пустая страница видео с `status=ok` подтверждает вызов, но не наличие видео.
В браузерном чате при первом smoke-test возникло «Не удалось загрузить этот
ответ»; это отдельная проблема отображения, её причина не установлена.
Успех вызова коннектора не означает, что текст ответа уже показан в чате.
Повторный короткий запрос с числовым community scope и точными `vk_status` /
`vk_wall_get` завершился видимым ответом об успешном соединении и ID поста;
ID совпал с независимым чтением через подключённый коннектор. Это подтверждает
ограниченный smoke-test, а не весь каталог или автоматическое обновление токенов.

## Как дополнять эту инструкцию

Воспроизведите проблему минимальным read-only запросом. Запишите дату,
версию MCP/закреплённую схему, метод, тип credentials, безопасный код ошибки,
исправление и отдельный read-back. Разделяйте отказ core и upstream VK.
Не сохраняйте ключи, private URL, имена участников и ответы личных сообщений.
Если шаг ещё не завершён, так и укажите; обход ограничений не является решением.
